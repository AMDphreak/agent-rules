= Bitwarden unlock scripts

Tokenless PowerShell helpers for local agents. Never commit live `BW_SESSION` values.

== Agent entry (session-aware machines)

When `BITWARDEN_SESSION_PERSIST = enabled` in harness (this desktop):

[source,powershell]
----
. "$env:USERPROFILE\ensure_bw_unlocked.ps1"
bw status
----

Restores a saved decrypt session before prompting. Persists after unlock to User env + `%USERPROFILE%\.bw-session.dpapi`.

== Install to profile

[source,powershell]
----
$src = "$env:USERPROFILE\.cursor\skills\bitwarden-unlock\scripts"
Copy-Item "$src\ensure_bw_unlocked.ps1", "$src\bw_session_store.ps1", `
  "$src\persist_bw_session.ps1", "$src\unlock_bitwarden_gui.ps1", `
  "$src\Show-PasswordDialog.ps1", "$src\unlock_bitwarden.ps1", `
  "$src\bw_login.ps1" `
  $env:USERPROFILE -Force
Copy-Item "$src\Show-PasswordDialog.ps1" $env:USERPROFILE
----

== Persist session (reuse across shells)

CLI session keys stay valid until `bw lock` / `bw logout` — no built-in timeout.

[source,powershell]
----
. "$env:USERPROFILE\ensure_bw_unlocked.ps1"
# or after manual unlock:
. "$env:USERPROFILE\persist_bw_session.ps1"
----

Storage:

* User-level `BW_SESSION` environment variable
* DPAPI file `%USERPROFILE%\.bw-session.dpapi` (CurrentUser scope)

== GUI unlock (OpenShellOrg + fallbacks)

`unlock_bitwarden_gui.ps1` uses:

1. `Show-PasswordDialog.ps1` — masked WinForms dialog (OpenShellOrg-style; lives in this folder)
2. OpenShellOrg `terminal-gui-prompts` `Show-InputDialog.ps1` path probe (for future 2FA text prompts)
3. `Get-Credential` — native Windows secure prompt
4. `Read-Host -AsSecureString` — last resort

== Bitwarden login paths (not unlock)

`bw login` supports interactive email/password, `--apikey`, and `--sso`. Unlock only needs the master password. OAuth/browser login is not a separate `bw` subcommand today — use `bw login` in your own terminal once per machine, then agents call unlock/GUI unlock.

=== Personal API key (automated login)

Env vars (set by `$env:USERPROFILE\bw-apikey.local.ps1` or the host secret store):

* `BW_CLIENTID` — personal API `client_id` (`user.*` prefix)
* `BW_CLIENTSECRET` — personal API `client_secret`

Install once:

[source,powershell]
----
Copy-Item "$env:USERPROFILE\.cursor\skills\bitwarden-unlock\scripts\bw-apikey.local.ps1.example" `
  "$env:USERPROFILE\bw-apikey.local.ps1"
Copy-Item "$env:USERPROFILE\.cursor\skills\bitwarden-unlock\scripts\bw_login.ps1" `
  "$env:USERPROFILE\bw_login.ps1"
# Edit bw-apikey.local.ps1 locally — never commit or paste secrets into chat
----

== AI safety

* Never `Read` `$env:USERPROFILE\unlock_bitwarden.ps1` if it may contain a hardcoded session.
* Never `Read` or print `$env:USERPROFILE\bw-apikey.local.ps1`, `BW_CLIENTSECRET`, `.bw-session.dpapi`, or item secrets.
* Never print `BW_SESSION`, item secrets, or `.env.local` values in chat.
* Always prefer `ensure_bw_unlocked.ps1` on machines with session persist enabled.
